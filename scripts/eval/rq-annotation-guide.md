# 改写质量评测集 · 标注指南

> **这份文件的作用**：说明 `rewrite-quality-eval.ts` 输出的 JSON 里每个字段怎么填，
> 并用第一个真值样本（「首创三态事实体系」）演示怎么判越界。

---

## 一、维度定义

| 维度 | 谁填 | 判据 |
|---|---|---|
| 照搬率 | 机器 | 逐字/近逐字照搬行数 / 总 resumeLines 行数；草案上限 10% |
| 厚度比 | 机器 | resumeLines 总字符 / 原简历总字符；阈值待校准（正样本区间 0.39-0.55） |
| fabricatedFactIds | 机器 | 硬线 = 0；任何非空 = 编造 |
| 越界行数 | **用户标** | 见下方「越界判断流程」 |

---

## 二、越界判断流程（逐行，人读）

**核心判据（D032 §二·附 + D005 边界，只有一条）**：

> 这件事实够不够格支撑写进去的这个强度/范围/角色？

**不是**「这个词在不在原文/事实库里」——词频判法已被用户驳回两次（D032 §二·附）。  
**不是**「这句话能不能被招聘者质疑」——任何能力标签都能被质疑，用这条会误杀合法专业命名。

**允许的**（D005:50「换专业术语命名真做过的事」）：
- 用专业术语重新命名真做过的事：`"完成了一个 RAG 系统"` → `"RAG 系统落地"`
- 丰满表述同一件事：`"参与开发"` + 事实是"独立完成四轮迭代" → 可以写"独立完成四轮迭代"

**不允许的**（强度超出事实支撑）：
- 范围扩大：事实是"参与"，写成"负责整个模块"
- 角色拔高：事实是"协助"，写成"主导"
- 限定词丢失：事实是"课程项目"，写成"项目"（丢掉了"课程"这个限定）
- 强度叠加：把三件普通的事叠成"精通 X、全面负责 Y、独立设计 Z"——任一件事实都支撑不起这个合力强度

---

## 三、overreachType 枚举说明

| 值 | 含义 | 例子 |
|---|---|---|
| `scope_expansion` | 范围扩大 | 事实："参与" → 写成"负责整个模块" |
| `role_elevation` | 角色拔高 | 事实："协助/参与" → 写成"主导/独立完成" |
| `qualifier_dropped` | 限定词丢失 | 事实："课程项目/原型/内测版本" → 丢掉限定词 |
| `strength_stacked` | 强度叠加 | 多件普通事叠成比任一件事实都更强的印象 |

## 五、首个真值标注样本（「首创」类，过度包装）

> **来源**：2026-08-04 用户真机走查（project-map.md:319-327，backlog.md:135-147）  
> **类别**：`strength_stacked` / 确切说是「给真实存在的事加了事实里没有的行业定位强度」

**生成的简历行（已知）**：
```
首创三态事实体系（已确认 / 待验证 / 不可用），实现简历内容零编造
```

**对应的事实原文（重建，非精确）**：
```
构建 confirmed / unconfirmed / rejected 个人事实库，限制材料生成只引用已确认事实，
避免 AI 编造学历、经历、项目、指标或技能
```

**越界分析**：
- 事实是：「产品用了三种状态管理事实」——**这是真的**，三态体系真实存在
- 但「首创」是对整个行业的主张：「这个人是第一个发明这种体系的」
- 没有任何事实支撑这个行业定位——这件事实只支撑「用了三态」，够不上「首创」

**正确标注**：
```json
"annotation": {
  "overreach": true,
  "overreachType": "strength_stacked",
  "note": "「首创」是行业定位主张，不是对这件事实的描述；事实只支撑「使用了三态」，不支撑「首创」"
}
```

**样本级结论**：
```json
"sampleAnnotation": {
  "overreachLineCount": 1,
  "verbatimRateOk": null,
  "thicknessOk": null,
  "verdict": "fail",
  "notes": "仅1处越界（首创），其余用户评价"差不离、都是可以引上去的"，属于pass边界"
}
```

**方法论价值**：
- 上一轮内容评测域自审报"越界 0 处"，用户一眼看出过度包装 → **域一级自审不成立**
- 这条样本是「为什么真值只能用户标」的实证（backlog.md:144）
- 注意：它没有编造事实（三态体系真实存在），机制层逐行溯源**放行是正确的**——  
  这正是「机制层管不到语义层」的实例，也是为什么#7 必须存在

## 六、跑一批样本的建议顺序

1. 先跑 `rewrite-quality-eval.ts`（一个岗位 = 一个样本）
2. 打开输出 JSON，逐行对照 `lines[].referencedFacts[].value` 和 `lines[].text`
3. 填 `annotation.overreach`（true/false）和可选的 `overreachType` + `note`
4. 所有行填完后，在 `sampleAnnotation` 里填 `overreachLineCount` / 指标判断 / `verdict`
5. 把 JSON 路径贴回首席

**覆盖建议**（backlog #7 要求必含半强度事实）：
- 要有「参与/协助/课程项目/原型」这类半强度事实的岗位样本
- 如果所有选取岗位对应的事实都是强事实，越界检测没有触发机会 ≠ 约束不需要
